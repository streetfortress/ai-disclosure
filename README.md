# AI Disclosure

Streetfortress Industries uses agentic development heavily. Since mid-late 2025, most lines
of code in our repositories have been generated by LLMs.

## What we promise

**Agents commit under their own identity.** Agent-authored changes are committed and signed as `sfi-agent`. Authorship in our repositories is data you can audit with git: `git log --author=sfi-agent`. We've found that when agent output 'masquerades' under a human account, the review process gets unnecessarily complicated fast. A dedicated user account just makes sense in hindsight.

**Every change gets _at least_ eyes-on by a person.** Our mains are branch-guarded and the agent role has no merge or approve permission. This is enforced _on the repository by policy_, not with a prompting.

**Code review is a discipline and happens frequently.** Not every change needs a big review. But significant changes, often done to improve efficiency or add new features, definitely still do. Nothing about AI has changed that. We reassess and refactor changes frequently in the development process - the "one prompt gets it all" situations are somewhat uncommon.

**Changes are tested before they reach you.** We run a robust suite of CI, dev, and staging environments behind the scenes. Code changes are not accepted without passing tests and deployments only reach production after acceptance testing. This is not a claim that our software is perfect, just a statement about our stance on code quality.

**We'll hand write the "user facing surface", but we accept verbose LLM output in the comments and generated docs.** Look, we get it. A wall of LLM spam can suck to get hit with. But the best way we've found to keep docs in sync with the code is for agents to make doc revisions _along with the change_. Think about it: All of the context around the change is there in the model anyway, better to dump it out into docs where it doesn't disappear when the session ends.

To that end:
- READMEs, getting started material, guides, etc: written by a human who uses and cares about the thing being written about
- Technical reference docs, code comments, commit messages, PR descriptions, etc: fair game to be 100% LLM generated in our code bases.

We believe that if an idea is worth pursuing, it's worth talking about - so therefore if you can't be bothered to write about it, it's not worth a code change in the first place.
### Ramblings
SFI is about ideas and building things. I never picked sides in the operating-system or text-editor wars, and we are not enlisting in this one (relevant xkcd: https://xkcd.com/378/). Tools change; review, testing, and standing behind your work... these practices are not going anywhere.

## Why we publish authorship

Most projects hide machine authorship because authorship carries
stigma. We publish it because, here, authorship carries no blame — and
that is an old discipline, not an AI-era invention. Gerald Weinberg
called it *egoless programming* in 1971: the code is the team's, not
the author's, and review examines the work rather than the person. The
blameless postmortem tradition made the same move for incidents: asking
*who* destroys the information flow that prevents the next one; asking
*what the system allowed* improves the system.

We apply both to authorship. Code review accepts the **intent and
direction** of a change; once it is accepted, the change belongs to the
team. Accountability did not vanish — it moved. It attaches to the
merge, not the keystrokes: the human who accepts a change owns it. And
when an incident happens anyway, the postmortem asks what the system
allowed, not who — or what — typed it. Systems get better by iteration,
and iteration requires that honesty stays cheap.

There is a practical reason this matters more now: change volume. When
changes can be produced faster than any one person can type, per-change
ego has to go to zero or review turns adversarial. Reviewing intent and
direction scales. Reviewing keystrokes does not.

## Contributions

The same rules apply inbound. AI-assisted contributions are welcome;
disclose the assistance, and own what you submit — you are the human
accepting intent and direction before we ever see it. Your change gets
the same review as ours. Undisclosed machine-generated pull requests
that waste reviewer time are closed without ceremony; the problem is
never the tool, it is submitting work nobody stood behind.
